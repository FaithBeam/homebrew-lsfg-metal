# homebrew-lsfg-metal

[Homebrew](https://brew.sh) tap for [lsfg-metal](https://github.com/FaithBeam/lsfg-metal), a macOS port of [lsfg-vk](https://github.com/PancakeTAS/lsfg-vk). It runs Lossless Scaling frame generation on Metal, for native Metal games and for Windows games under Wine (D3DMetal / Game Porting Toolkit, CrossOver, Sikarugir, DXVK/MoltenVK, DXMT).

lsfg-metal ships no shaders. You need your own copy of **Lossless Scaling** from Steam, which provides `Lossless.dll`.

> [!WARNING]
> lsfg-metal is injected into the game's process and hooks its Metal calls. Anti-cheat software may treat that as cheating. **Use it in single-player and offline games only.** See the [upstream warning](https://github.com/FaithBeam/lsfg-metal#readme) for details.

## Install

```sh
brew install FaithBeam/lsfg-metal/lsfg-metal
```

Or tap first, then install by name:

```sh
brew tap FaithBeam/lsfg-metal
brew install lsfg-metal
```

The formula builds from source, so CMake is pulled in as a build dependency. The library is built universal (arm64 + x86_64), because Wine, CrossOver and D3DMetal games run as x86_64 under Rosetta 2 while native games are usually arm64.

To build the latest `main` instead of the latest release:

```sh
brew install --HEAD FaithBeam/lsfg-metal/lsfg-metal
```

## What gets installed

| File | Purpose |
|---|---|
| `lib/liblsfg-metal.dylib` | the frame generation library, loaded into games with `DYLD_INSERT_LIBRARIES` |
| `bin/lsfg-metal-run` | run a native game or plain `wine` with the library injected |
| `bin/lsfg-metal-sikarugir` | launch a Sikarugir / Kegworks / Wineskin wrapper with the library injected |
| `bin/lsfg-metal-crossover` | enable lsfg-metal for CrossOver bottles and launch programs in them |
| `bin/lsfg-metal-cli` | find `Lossless.dll`, validate shaders, benchmark |

## Quick start

Check that your `Lossless.dll` is found:

```sh
lsfg-metal-cli find-dll
```

Then launch a game:

```sh
# Native Metal game
lsfg-metal-run -m 2 /Applications/SomeGame.app

# Native Steam game: set its launch options to
#   $(brew --prefix)/bin/lsfg-metal-run -m 2 %command%
# with $(brew --prefix) written out, e.g. /opt/homebrew/bin/lsfg-metal-run

# Sikarugir / Kegworks / Wineskin wrapper (the wrapper is not modified)
lsfg-metal-sikarugir -m 2 ~/Applications/Sikarugir/MyGame.app

# CrossOver (CrossOver.app is not modified)
lsfg-metal-crossover enable Steam
lsfg-metal-crossover run Steam "C:\\Program Files (x86)\\Steam\\steam.exe"

# Plain wine / Game Porting Toolkit
export DYLD_INSERT_LIBRARIES="$(brew --prefix)/lib/liblsfg-metal.dylib"
wine game.exe
```

Per-game settings live in `~/.config/lsfg-metal/conf.toml`, created on first run. See the upstream [Usage](https://github.com/FaithBeam/lsfg-metal#usage) and [Configuration](https://github.com/FaithBeam/lsfg-metal#configuration) sections for profiles, environment variables, logging and troubleshooting.

## Upgrading

```sh
brew update
brew upgrade lsfg-metal
```

CrossOver bottles enabled with `lsfg-metal-crossover enable` point at a copy of the library in `~/Library/Application Support/lsfg-metal`, not at the Homebrew path. Every `lsfg-metal-crossover run` refreshes that copy, so bottles keep working across upgrades.

## Uninstall

Disable any CrossOver bottles first, so they no longer reference the library:

```sh
lsfg-metal-crossover disable Steam
brew uninstall lsfg-metal
brew untap FaithBeam/lsfg-metal
```

Optionally remove the leftover data:

```sh
rm -rf ~/Library/Application\ Support/lsfg-metal   # CrossOver clone and library copy
rm -rf ~/.config/lsfg-metal                        # config
```

## About this tap
